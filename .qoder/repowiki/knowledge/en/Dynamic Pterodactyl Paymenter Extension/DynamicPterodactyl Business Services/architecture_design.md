Services/ is the composition root for all domain logic in the DynamicPterodactyl extension. `ReservationService` owns the reservation lifecycle (create with pessimistic locking + idempotency key, confirm/cancel/extend, TTL cleanup) and coordinates with `NodeSelectionService`, which selects the best-fit node using a weighted headroom algorithm over memory (50%), disk (35%), CPU (15%). `ResourceCalculationService` is the single abstraction over the Pterodactyl REST API — it fetches locations/nodes/servers, aggregates per-node availability accounting for overallocation and pending reservations, builds cluster snapshots, and degrades gracefully when the upstream API is unavailable. `AlertService` is the scheduled entry point (every 5 min, withoutOverlapping) that scans active `ptero_alert_configs`, computes memory/disk utilization thresholds, and delivers via email (`CapacityAlertNotification`) or Discord-compatible webhook, tracking delivery outcomes in `AlertDeliveryLog` with per-config cooldown. `AuditLogService` writes to `ptero_audit_logs`; cross-cutting audit writes are injected via the `AuditsExtensionActions` trait's `safeAudit()` helper, which wraps calls in try/catch so audit failures never break the calling flow. Dependency direction is one-way: ReservationService → NodeSelectionService → ResourceCalculationService; AlertService depends on ResourceCalculationService only. All services use raw DB queries against `ptero_*` tables rather than Eloquent models, keeping them framework-light and testable.
