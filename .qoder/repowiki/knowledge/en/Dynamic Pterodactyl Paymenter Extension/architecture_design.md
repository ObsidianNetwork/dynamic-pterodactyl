DynamicPterodactyl.php is the single boot/composition root: it registers routes, view namespaces, model observers, policies, two Laravel schedules (reservation cleanup every minute, capacity alert scanning every five minutes), and four Paymenter event listeners (CartItemCreated/Deleted, InvoicePaid, ServiceCreated) that translate checkout lifecycle events into ReservationService calls. The runtime splits into thin HTTP controllers (validation + delegation), a Services layer (business logic, Pterodactyl integration, AlertService scheduled task), domain Models with Observers (audit redaction), Filament Admin Resources/Pages for CRUD and dashboards, and a self-contained tests harness that boots a real Paymenter app against an in-memory DB. Cross-cutting audit writes go through the AuditsExtensionActions trait so all services log consistently without full tokens.
