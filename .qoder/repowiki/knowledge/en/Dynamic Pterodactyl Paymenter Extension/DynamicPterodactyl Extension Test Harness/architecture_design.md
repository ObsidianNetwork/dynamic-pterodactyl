The harness is split into two base classes: `TestCase.php` provides raw PHPUnit + Mockery with lightweight fixture helpers (`createPricingConfig`, `createNodeData`, `standardResources`) for pure service tests; `LaravelTestCase.php` extends Laravel's `BaseTestCase`, bootstraps the parent Paymenter app via `bootstrap/app.php`, and adds slider/node fixture builders plus a full `createConfigOption()` mock implementing dynamic pricing models. `bootstrap.php` is the entry point that autoloads the host vendor, enforces a hard guard requiring `DB_DATABASE` to be `paymenter_test`, `:memory:`, or empty (exiting with code 2 otherwise), then requires both base classes. Tests are organized by concern rather than layer: `Unit/` covers services, request validation, listeners, and observers (some intentionally DB-backed under `DatabaseTransactions`), while `Feature/` targets externally observable surfaces — API routes, authorization shape, schedule registration, and wizard flows. Feature tests explicitly `require __DIR__ . '/../../routes/api.php'` in `setUp()` because extension routes are loaded at runtime by `DynamicPterodactyl::boot()`, not auto-discovered. The `AlertServiceTest` class is a special case extending raw `TestCase` and running in separate processes with global state disabled to isolate facade alias mocking.
