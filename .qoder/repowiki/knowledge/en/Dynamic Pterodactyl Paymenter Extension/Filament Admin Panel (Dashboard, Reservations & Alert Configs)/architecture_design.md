Two-layer Filament surface under `Admin/`: standalone `Pages/*` classes extend `Filament\Pages\Page` and render Blade templates via a `protected string $view` binding (e.g. `dynamic-pterodactyl::admin.dashboard`, `setup-wizard`, `node-monitoring`, `audit-log`), while `Resources/*` extend `Filament\Resources\Resource` to expose model-backed tables and forms. Each resource registers nested page classes through `getPages()` — `AlertConfigResource` exposes create/edit/list pages under `Resources/AlertConfigResource/Pages/`, and `ReservationResource` exposes only a read-only list page because `canCreate()` returns `false`. All state-changing table actions route through domain services (`ReservationService`, `AlertService`, `ResourceCalculationService`) rather than mutating models directly; Pages similarly delegate data gathering to services like `ConfigOptionSetupService` and `ReservationService`. Navigation is grouped under the `Dynamic Pterodactyl` group with explicit `navigationSort` values to preserve menu order. Views live outside this directory at `../resources/views/admin/` and are referenced by fully qualified view names.
