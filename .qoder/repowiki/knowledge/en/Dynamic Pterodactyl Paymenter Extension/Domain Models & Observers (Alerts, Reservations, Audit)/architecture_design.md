Models live under `Paymenter\Extensions\Others\DynamicPterodactyl\Models` and map to Pterodactyl tables prefixed with `ptero_` (`ptero_alert_configs`, `ptero_resource_reservations`, `ptero_audit_logs`, `ptero_alert_delivery_log`). Each model is a thin Eloquent entity: it declares `$table`, `$fillable`, `$casts`, and relationships — no business logic. Cross-model links are defined via Eloquent relations: `AlertConfig::hasMany(AlertDeliveryLog)` and `AlertDeliveryLog::belongsTo(AlertConfig)`; `ResourceReservation` belongs to external `App\Models\User` and `App\Models\Service`. Query scoping is centralized in model scopes (`scopeGlobal`, `scopeForLocation`, `scopePending`, `scopeExpired`) rather than scattered where clauses. An observer sub-namespace (`Models\Observers\AlertConfigObserver`) hooks into created/updated/deleted events on `AlertConfig`, sanitizes `webhook_url` via a private `redactWebhook` helper, and delegates persistence to `AuditLogService` from the Services layer, keeping observers as pure side-effect adapters. The `AuditLog` model disables automatic timestamps and stores old/new values as JSON arrays for diff-based change tracking.
